## 1. Принципы

1. Тест подтверждает требование только если его можно воспроизвести и он записан в TEST_RESULTS.md (файл будет создан с первыми результатами).
2. Статус NOT VERIFIED снимается только результатом теста.
3. Mock и stub допускаются только в тестах. Сквозные тесты блокировки выполняются на реальной ОС, реальном драйвере в тестовой подписи и реальных компонентах.
4. Для механизмов блокировки обязательны негативные тесты, fault injection, нагрузочные тесты и тесты совместимости с EDR/AV.
5. Тесты не удаляются ради прохождения CI.

## 5. Качество обнаружения

Precision и recall каждого детектора измеряются на эталонном корпусе из синтетических данных (DLP-DETECTION-015). Пороги утверждает офицер ИБ после первого замера. Сценарии FID/UC-01…UC-08 — кандидаты приёмочных сценариев (U-13), на согласовании.
