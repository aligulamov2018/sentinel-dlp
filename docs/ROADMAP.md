## 2. Обязательные ограничения из решений

- **D-03.** Первым реализуется `sentinel-core` с CLI `sentinel-scan`; параллельно — три spike. Начало разработки производственного кода требует отдельного подтверждения владельца (решение от 2026-11-10).
- **D-04.** Порядок ОС: Windows → Linux → macOS; условно до ответа на Q-02.
- **D-05.** Каждое блокирующее правило сначала работает в режиме Monitor на представительной пилотной группе. Контентная блокировка записи на USB не заявляется до SPIKE-WIN-01.
- **D-07.** `FULL_EVIDENCE` не входит в MVP по умолчанию до решения по Q-04.
- **D-08.** Каналы X-01…X-04 не входят в версию 1.
- **D-12.** Network PoC не входит в критерии выхода MVP и не заменяет блокировку Windows MVP. Если SPIKE-WIN-01 не подтвердит блокировку Windows MVP, объём MVP пересматривается отдельным решением владельца; сетевой канал автоматически в MVP не переносится.
- **D-13.** Поставка RPM/DEB + systemd — предварительно, до ответа о серверных платформах и Q-03; OCI-образ не обязателен в MVP.
- **D-14.** Изоляция разбора не расширяет набор форматов Windows MVP; механизм выбирается по TC-D14-05 и SPIKE-WIN-01.
- **D-15.** Число процессов агента и механизм watchdog фиксируются после SPIKE-WIN-01.
- **D-16.** `FULL_EVIDENCE` не включается до решения по Q-04; бэкенд хранилища evidence выбирается к пилоту.
- **D-17.** BLOCK без подтверждённого BLOCK_CAPABLE не компилируется; понижение — только по исключению ADR-0019.

## 3. Критерии перехода

| Шлюз | Критерии (Proposed) |
| --- | --- |
| G1: Фаза 0 → MVP | ADR-0001…0006, 0016, 0017 приняты; документация CHG-0002 и CHG-0003 прошла архитектурное ревью; решения по C-01…C-06 приняты (D-12…D-17, 2026-11-11), незавершённые проверки D-12…D-16 перечислены в DECISION_LOG.md §3; отчёты трёх spike; заявки на EV-сертификат и entitlement Apple поданы; защита веток `main` и `develop` включена |
| G2: MVP → пилот | Все функции MVP в статусе Tested; TC-D05-01…17, TC-D05-19…23 и TC-D06-01…55 пройдены на стенде с EDR организации (TC-D05-18 — только если L3 входит в объём после SPIKE-WIN-01); TC-D05-24 выполнен с записью результата по каждому гипервизору парка; механизм изоляции разбора (D-14) и механизм восстановления агента (D-15) утверждены владельцем, TC-D14-01…06 пройдены, в том числе TC-D14-05 — измеренная задержка укладывается в утверждённый бюджет синхронного пути (при отсутствии утверждённого бюджета или его превышении механизм D-14 остаётся NOT VERIFIED и вопрос возвращается владельцу); TC-D15-01, TC-D15-02, TC-D16-01, TC-D17-01…06 пройдены; TC-D16-02 (бэкенд evidence) — критерий пилота, а не выхода MVP; TC-D13-01 пройден на целевой серверной ОС; результаты Network PoC (TC-D12-01) критерием не являются; Driver Verifier без нарушений; бюджет производительности измерен; драйвер подписан для рабочих ПК; правовая основа мониторинга утверждена (Q-04) |
| G3: пилот → Production | Пилотная группа отработала в Monitor, затем в Block без нарушения работы; доля ложных блокировок ниже порога ИБ; восстановление из копии и переключение HA проверены; внешний пентест без открытых критических находок; DEPLOYMENT_GUIDE.md и ADMINISTRATOR_GUIDE.md проверены чистой установкой |
| Выпуск 1.0 | Эксплуатационная приёмка; статус Production Ready — только функциям, прошедшим приёмку |

Даты не назначены: они зависят от ответов на Q-08 (команда) и Q-09 (сроки и бюджет).
