## 2. Обязательные ограничения из решений

- **D-03.** Первым реализуется `sentinel-core` с CLI `sentinel-scan`; параллельно — три spike. Начало разработки производственного кода требует отдельного подтверждения владельца (решение от 2026-11-10).
- **D-04.** Порядок ОС: Windows → Linux → macOS; условно до ответа на Q-02.
- **D-05.** Каждое блокирующее правило сначала работает в режиме Monitor на представительной пилотной группе. Контентная блокировка записи на USB не заявляется до SPIKE-WIN-01.
- **D-07.** `FULL_EVIDENCE` не входит в MVP по умолчанию до решения по Q-04.
- **D-08.** Каналы X-01…X-04 не входят в версию 1.

## 3. Критерии перехода

| Шлюз | Критерии (Proposed) |
| --- | --- |
| G1: Фаза 0 → MVP | ADR-0001…0006, 0016, 0017 приняты; документация CHG-0002 и CHG-0003 прошла архитектурное ревью; решения по C-01…C-06 приняты или их риски приняты явно; отчёты трёх spike; заявки на EV-сертификат и entitlement Apple поданы; защита веток `main` и `develop` включена |
| G2: MVP → пилот | Все функции MVP в статусе Tested; TC-D05-01…17, TC-D05-19…23 и TC-D06-01…55 пройдены на стенде с EDR организации (TC-D05-18 — только если L3 входит в объём после SPIKE-WIN-01); TC-D05-24 выполнен с записью результата по каждому гипервизору парка; Driver Verifier без нарушений; бюджет производительности измерен; драйвер подписан для рабочих ПК; правовая основа мониторинга утверждена (Q-04) |
| G3: пилот → Production | Пилотная группа отработала в Monitor, затем в Block без нарушения работы; доля ложных блокировок ниже порога ИБ; восстановление из копии и переключение HA проверены; внешний пентест без открытых критических находок; DEPLOYMENT_GUIDE.md и ADMINISTRATOR_GUIDE.md проверены чистой установкой |
| Выпуск 1.0 | Эксплуатационная приёмка; статус Production Ready — только функциям, прошедшим приёмку |

Даты не назначены: они зависят от ответов на Q-08 (команда) и Q-09 (сроки и бюджет).
