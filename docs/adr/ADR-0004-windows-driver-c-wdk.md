# ADR-0004. Драйвер перехвата Windows: минимальный minifilter на C (WDK)

| Атрибут | Значение |
| --- | --- |
| Назначение | Определить язык и границы ответственности драйвера ядра Windows |
| Версия | 2 (уточнение по D-05, CHG-0003) |
| Дата | 2026-11-10 |
| Статус | Accepted |
| Решение владельца | D-02 (DECISION_LOG.md), согласовано 2026-11-10; ограничения D-05 добавлены в версии 2 |
| Связанные требования | CLAUDE.md §4.1; ARCH-0001 §7, §10 (T-02, T-11), §14 (R-01, R-03, R-12) |
| Затронутые компоненты | Endpoint Agent (Windows): драйвер и сервис |

## Контекст

Синхронная блокировка записи на съёмные носители в Windows требует file system minifilter в режиме ядра. Ошибка в драйвере ядра приводит к отказу ОС (BSOD) на рабочих станциях. Для загрузки драйвера на современных Windows нужна подпись Microsoft через Partner Center, а для неё — EV-сертификат организации. Microsoft разрабатывает Windows Endpoint Security Platform (WESP), которая в будущем может позволить отказаться от собственного драйвера. По данным Elastic Security Labs от 26.10.2026, платформа на ранней стадии и доступна только в Insider-сборках.

## Рассмотренные варианты

1. **C с Windows Driver Kit** — стандартный, документированный путь, совместимый с Driver Verifier, HLK и примерами Microsoft.
2. **Rust для драйверов Windows** (windows-drivers-rs) — безопасность памяти, но экосистема созревает, а пригодность для промышленного minifilter не подтверждена.
3. **Без драйвера** — только user-mode-мониторинг. Синхронная блокировка невозможна.

## Решение

Вариант 1. Драйвер минимален:

- регистрирует pre-operation callbacks для операций, нужных политике (create с правом записи, write, set-information) на томах съёмных носителей;
- передаёт запрос решения сервису агента через communication port Filter Manager;
- ждёт ответа не дольше заданного таймаута, затем применяет fail-режим из политики;
- не содержит логики детектирования и политик — это делает сервис агента на Rust (ADR-0003).

Интерфейс между драйвером и сервисом оформляется как PEP-адаптер, чтобы позже можно было перейти на WESP без изменения логики решений.

## Обоснование

Минимальный объём кода в ядре — главная мера против риска R-03. C с WDK — путь с наибольшим количеством документации, инструментов проверки и опыта сертификации.

## Последствия

- Обязательны Driver Verifier, статический анализ (CodeQL для драйверов) и HLK-тесты перед выпуском.
- Раскатка только кольцами (тестовая группа → пилот → все) с механизмом аварийного отключения перехвата без удаления агента.
- До получения EV-сертификата и подписи Microsoft драйвер работает только на стенде в тестовом режиме подписи.

## Риски

| Риск | Мера |
| --- | --- |
| R-01: нет EV-сертификата и аккаунта Partner Center | Оформление в фазе 0, параллельно с разработкой ядра |
| R-03: нет инженера с опытом драйверов | Найм или привлечение специалиста до начала SPIKE-WIN-01 в промышленном объёме |
| R-04: конфликт с EDR/AV организации | Тесты совместимости на стенде с установленным EDR |

## Условия пересмотра

Появление в WESP документированной блокировки из user mode или зрелость Rust-драйверов, подтверждённая сертификацией.

## Уточнение версии 2 (D-05, 2026-11-10)

Ограничения D-05 применяются к драйверу без расширительного толкования. Подробности — docs/architecture/FAILURE_MODE_DESIGN.md §5–§8 и ADR-0016.

- Драйвер — только PEP. Решение принимает PDP в сервисе; при отсутствии ответа драйвер применяет fallback из таблицы, переданной сервисом, а не собственную логику.
- `FltSendMessage` всегда вызывается с конечным таймаутом. `Timeout = NULL` означает бесконечное ожидание и запрещён. `STATUS_TIMEOUT` — код успеха, поэтому обрабатывается явно. Обрабатываются все документированные NTSTATUS. IRQL ≤ APC_LEVEL. Сведено по Microsoft Learn 2026-11-10.
- Число ожидающих запросов ограничено; ожидание не выполняется с удержанием блокировок; собственный I/O сервиса не перехватывается.
- Гарантия fail-closed до подключения сервиса не заявляется до подтверждения в SPIKE-WIN-01.
- Группа порядка загрузки (FSFilter Content Screener 260000–269999 или FSFilter Activity Monitor 360000–389999) и заявка на высоту — вопрос SPIKE-WIN-01.
