# ADR-0003. Язык ядра детектирования, агента, шлюзов и сканера: Rust

| Атрибут | Значение |
| --- | --- |
| Назначение | Выбрать язык для кода, который разбирает недоверенное содержимое и работает на endpoint |
| Версия | 1 |
| Дата | 2026-11-10 |
| Статус | Accepted |
| Решение владельца | D-02 (DECISION_LOG.md), согласовано 2026-11-10 |
| Связанные требования | CLAUDE.md §4.1, §4.2, §5; ARCH-0001 §5, §8, §10 (T-05) |
| Затронутые компоненты | Detection Engine (`sentinel-core`), Policy Decision Point, Endpoint Agent (сервис), `sentinel-gateway`, `sentinel-scanner` |

## Контекст

Ядро детектирования разбирает файлы, которые может подготовить нарушитель: OOXML, PDF, архивы. Это основная поверхность атаки (угроза T-05). Тот же код выполняется на рабочих станциях, где важны предсказуемые задержки и малый расход памяти. Одна и та же логика решений должна работать в агенте, шлюзах и сканере, чтобы одинаковый файл получал одинаковое решение в любом канале.

## Рассмотренные варианты

| Вариант | Плюсы | Минусы |
| --- | --- | --- |
| C++ | Максимальная производительность, зрелые парсеры | Ошибки памяти в парсерах недоверенных данных — исторически основной класс уязвимостей |
| Go | Единый язык с сервером | Сборщик мусора на горячем пути блокирующего решения; больший размер агента |
| Rust | Безопасность памяти без сборщика мусора; предсказуемые задержки; хорошее FFI с C и Swift | Длиннее обучение; часть парсеров форматов менее зрелая, чем на C++ |

## Решение

Rust. Ядро оформляется как библиотека `sentinel-core` (Cargo workspace) с CLI `sentinel-scan`. Агент, шлюзы и сканер используют эту библиотеку напрямую.

## Обоснование

Безопасность памяти при разборе недоверенных форматов — главный аргумент. Отсутствие сборщика мусора важно для задержки решения на endpoint. Одна библиотека во всех точках контроля даёт единые результаты и единый набор тестов.

## Последствия

- `unsafe` допускается только в явно отмеченных модулях (FFI с драйвером, системные вызовы) с комментарием-обоснованием и ревью.
- Каждый парсер покрывается фаззингом (`cargo-fuzz`).
- Обязательные проверки в CI: `cargo fmt`, `clippy` без предупреждений, `cargo audit`, `cargo deny` (лицензии и источники зависимостей).
- Сторонние crates проходят ревью: лицензия, сопровождение, наличие `unsafe`.

## Риски

| Риск | Мера |
| --- | --- |
| Незрелость отдельных парсеров (например, PDF) | Оценка crates до выбора; лимиты ресурсов; при необходимости — изолированный процесс с внешним парсером |
| Нехватка Rust-разработчиков | Обучение, строгие соглашения, обязательное ревью |
| Недоступность реестра crates.io в среде разработки | Зеркало или вендоринг зависимостей (`cargo vendor`) для изолированной сборки — требуется для air-gapped поставки в любом случае |
