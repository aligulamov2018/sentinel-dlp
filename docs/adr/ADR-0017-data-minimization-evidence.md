# ADR-0017. Минимизация данных по умолчанию и защита evidence

| Атрибут | Значение |
| --- | --- |
| Назначение | Определить уровни передачи данных с endpoint и шлюзов, хранение и доступ к evidence |
| Версия | 3 (уточнения по ревью AR-07, AR-08 и раунда 2; статус не меняется) |
| Дата | 2026-11-10 |
| Статус | Accepted with constraints |
| Решение владельца | D-07 (DECISION_LOG.md), 2026-11-10 |
| Связанные документы | docs/security/DATA_PROTECTION_DESIGN.md, docs/DATA_MODEL.md, docs/THREAT_MODEL.md |
| Затронутые компоненты | Detection Engine (маскирование), Endpoint Agent, `sentinel-gateway`, Incident Management, хранилище evidence, резервное копирование, журналирование |
| Происхождение | ARCH-0001 §3, §9; FID/ADR-012 — расхождение по умолчанию разрешено приоритетом D-07 (RES-04) |

## Контекст

DLP обрабатывает содержимое документов сотрудников. Полные копии делают DLP самостоятельной целью атаки и источником правового риска. Правовая основа сбора полного содержимого (Q-04) не подтверждена.

## Рассмотренные варианты

1. Всегда сохранять копии.
2. Никогда не сохранять копии.
3. По умолчанию хеш и маскированный фрагмент; копия — по явной политике (FID/ADR-012).
4. **Privacy by Default: по умолчанию только метаданные; маскированные фрагменты — только когда их требует политика; полная копия — только по явному действию опубликованной политики и при выполнении правовых требований.**

## Решение

Вариант 4. Уровни передачи:

| Уровень | Содержание | Когда разрешён |
| --- | --- | --- |
| `METADATA` | Минимально необходимые сведения о событии (DATA_MODEL.md §3) | По умолчанию |
| `MASKED_MATCH` | Ограниченное число маскированных фрагментов | Только если действие правила явно запрашивает этот уровень |
| `FULL_EVIDENCE` | Полная копия объекта | Только по явному действию опубликованной политики, при включённой на уровне платформы возможности сбора (двойной контроль) и после согласования правовой основы (Q-04) |

Ограничения:

- До решения по Q-04 правомерность `FULL_EVIDENCE` не утверждается. Функция не включается в MVP по умолчанию; возможность сбора на уровне платформы по умолчанию выключена.
- Пути файлов, имена пользователей, хеши и маскированные фрагменты считаются потенциально идентифицирующими данными и тоже подлежат минимизации. Полный путь файла по умолчанию не передаётся; по умолчанию — класс расположения и псевдоним пути (Proposed, DATA_PROTECTION_DESIGN.md §2.1). Область и размещение ключа псевдонимизации — Pending, решение владельца.
- Метаданные и evidence хранятся раздельно; evidence шифруется отдельными ключами (конвертное шифрование, KEK во внешнем KMS или HSM — как архитектурная возможность).
- Доступ к evidence — только через API сервера с проверкой прав и аудитом. Консоль не имеет прямого доступа к БД.
- Чувствительное содержимое запрещено в отладочных логах, трассировках и аварийных дампах.

## Последствия

- Расследования, требующие полного содержимого, зависят от явной политики сбора; это осознанное ограничение.
- Нужны: модель прав на просмотр, экспорт и удаление; двойной контроль массовых экспортов; сроки хранения и legal hold; crypto-shredding; защита резервных копий; внешнее закрепление целостности аудита.

## Риски

| Риск | Мера |
| --- | --- |
| Недостаточность метаданных для расследования | Уровень `MASKED_MATCH` по правилу; пересмотр после пилота |
| Повторная идентификация по маскированным фрагментам | Ограничение длины и числа фрагментов; маскирование по типу данных (DATA_PROTECTION_DESIGN.md §3) |
| Удалённое evidence остаётся в резервных копиях | Ключи периода KEK_P, их уничтожение после срока хранения копий, повторное применение журнала удалений при восстановлении (DATA_PROTECTION_DESIGN.md §7); остаточный риск R-21 |
